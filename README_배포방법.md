# 개미는 뚠뚠 — 웹앱 배포 가이드 (Render.com 무료 호스팅)

이 폴더를 인터넷에 올리면, 집이 아니어도 폰 브라우저에서 언제든 종목을 검색할 수 있습니다.
아래 순서대로 따라 하면 됩니다. 전부 무료로 가능합니다 (Render 무료 플랜 기준).

전체 흐름: **① GitHub에 코드 올리기 → ② Render에서 배포 → ③ API 키 등록 → ④ 폰에 추가**

---

## 0. 준비물

- GitHub 계정 (없으면 github.com 에서 무료 가입)
- Render 계정 (render.com 에서 GitHub 계정으로 바로 가입 가능, 무료)
- 한국투자증권 KIS Open API 앱키 / 앱시크릿 (기존에 쓰던 것 그대로 사용)

> **중요**: 앱키/앱시크릿은 이 폴더 안 어떤 파일에도 들어있지 않습니다. 아래 3번 단계에서
> Render의 "환경변수" 설정 화면에만 입력하게 됩니다. GitHub에는 절대 올라가지 않으니 안심하세요.

---

## 1. GitHub에 코드 올리기

1. github.com 에서 로그인 → 오른쪽 위 **+** 버튼 → **New repository**
2. Repository name: `gaemi-ddundun` (원하는 이름으로 가능)
3. Public/Private 상관없음 (Private 추천 — 어차피 코드 자체엔 비밀정보가 없지만 굳이 공개할 필요는 없음)
4. **Create repository** 클릭
5. 생성된 페이지에 나오는 안내대로, 이 `gaemi_ddundun_web` 폴더 전체를 업로드합니다.
   - 가장 쉬운 방법: 저장소 페이지에서 **Add file → Upload files** 클릭 → 이 폴더 안의
     모든 파일(app.py, gaemi_ddundun.py, requirements.txt, Procfile, static 폴더,
     customs_*.json 6개, analyst_targets.json)을 통째로 드래그 앤 드롭 → 아래
     **Commit changes** 클릭

   (git 명령어에 익숙하면 `git init` → `git add .` → `git commit` → `git push` 로도 가능합니다.)

---

## 2. Render에서 배포

1. render.com 접속 → **Get Started** → GitHub 계정으로 로그인/가입
2. 대시보드에서 **New +** → **Web Service** 선택
3. 방금 만든 `gaemi-ddundun` 저장소를 선택하고 **Connect**
4. 설정 화면에서:
   - **Name**: 아무 이름 (예: `gaemi-ddundun`) — 이게 나중에 URL의 일부가 됩니다
     (예: `https://gaemi-ddundun.onrender.com`)
   - **Region**: Singapore (한국에서 가장 가까움)
   - **Branch**: main
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn app:app` (Procfile이 있으면 자동으로 채워질 수도 있음)
   - **Instance Type**: **Free** 선택
5. 아직 **Create Web Service** 버튼은 누르지 말고, 바로 아래 3번 단계로 이어서 환경변수부터 등록하세요.

---

## 3. API 키를 환경변수로 등록 (가장 중요한 단계)

같은 설정 화면(또는 배포 후 서비스 페이지의 **Environment** 탭)에서 **Environment Variables** 섹션을 찾아
**Add Environment Variable**을 두 번 눌러 아래 두 개를 추가합니다:

| Key | Value |
|---|---|
| `KIS_APPKEY` | (본인의 KIS 앱키) |
| `KIS_APPSECRET` | (본인의 KIS 앱시크릿) |

입력이 끝나면 **Create Web Service** (또는 **Save Changes**)를 클릭합니다.
Render가 자동으로 빌드하고 배포를 시작합니다 (2~5분 정도 소요). 로그 화면에서
`Running on http://0.0.0.0:...` 같은 메시지가 뜨면 완료입니다.

배포가 끝나면 서비스 페이지 상단에 `https://<서비스이름>.onrender.com` 형태의 주소가 나타납니다.
이 주소가 폰에서 접속할 최종 URL입니다.

---

## 4. 폰에서 "앱처럼" 쓰기 (홈 화면에 추가)

배포된 URL을 폰 브라우저(사파리 또는 크롬)로 열어보세요. 정상적으로 검색 화면이 뜨면:

**아이폰 (사파리)**
1. 하단 공유 버튼(네모+화살표) 탭
2. **홈 화면에 추가** 선택
3. 이름 확인 후 **추가**

**안드로이드 (크롬)**
1. 오른쪽 위 점 3개 메뉴 탭
2. **홈 화면에 추가** 선택
3. 이름 확인 후 **추가**

이렇게 하면 홈 화면에 "개미는 뚠뚠" 아이콘이 생기고, 탭하면 주소창 없이 앱처럼 바로 열립니다.

---

## 5. 사용법

홈 화면 아이콘(또는 브라우저로 접속한 URL)에서:

1. 종목코드 6자리 입력 (예: `005930`)
2. 종목명은 선택 입력 (안 넣어도 동작함, 리포트 제목에만 표시됨)
3. **검색** 누르면 리포트가 뜸

리포트에는 세 종류의 신호가 나옵니다:

- **PER/PBR 밸류에이션** — 자기 과거 평균 대비 지금이 비싼지 싼지 (펀더멘털 기준)
- **매수 타이밍 신호 (다이버전스)** — 최근 일봉 데이터로 거래량(OBV)·RSI 다이버전스를 감지해서,
  밸류에이션과는 별개로 "추세가 꺾일 조짐이 있는지"를 보여줌 (기술적/모멘텀 기준). 예를 들어
  밸류에이션은 "매우고평가"여도, 주가가 저점을 낮추는 동안 거래량과 RSI는 오히려 저점을
  높이고 있다면(매도 압력 약화) "강세 다이버전스"로 표시됩니다. 이 섹션은 일봉 데이터를
  여러 번 나눠 받아오기 때문에 리포트 생성이 몇 초 더 걸립니다.
- **수출입데이터 상관관계** — 관세청 품목별 수출입실적과 주가의 상관관계 (아래 4종목만 해당)
- **애널리스트 목표주가 & 선행 밸류에이션** — 증권사 리포트를 보고 `analyst_targets.json`에
  직접 입력해둔 목표주가/선행 배수 데이터 (해당 종목에 입력된 데이터가 있을 때만 표시).
  KIS API로 자동 갱신되는 게 아니라 사람이 직접 채워넣는 파일이라, 새 리포트가 나오면
  이 파일을 수정하고 GitHub에 다시 올려야 반영됩니다.

현재 종목-품목 상관관계 데이터(수출입 데이터 기반)가 붙어있는 종목:

- 삼성전자 (005930): DRAM / HBM·MCP / NAND
- SK하이닉스 (000660): DRAM / HBM·MCP / NAND
- 삼성전기 (009150): MLCC / 카메라모듈
- LG이노텍 (011070): 카메라모듈 / PCB(기타, 반도체기판 근사치)

다른 종목도 코드만 알면 검색은 되지만, 위 4종목 외에는 밸류에이션(PER/PBR 히스토리) 부분만
나오고 수출입 상관관계 섹션은 표시되지 않습니다.

## 알아두면 좋은 점 (무료 플랜의 한계)

- **자동 절전(cold start)**: Render 무료 플랜은 15분간 요청이 없으면 서버가 잠듭니다.
  이 상태에서 검색하면 첫 로딩에 30초~1분 정도 걸릴 수 있습니다 (서버가 깨어나는 시간).
  두 번째 검색부터는 빠릅니다. 이게 불편하면 유료 플랜(월 $7~)으로 올리면 항상 켜져 있습니다.
- **수출입데이터는 고정 스냅샷**: 배포 시점에 있던 customs_*.json 파일 기준으로 상관관계를
  계산합니다. 관세청 데이터가 새로 갱신되면, 로컬에서 `customs_export.py`로 새로 받은
  JSON 파일을 GitHub 저장소에 다시 올리고 Render가 재배포하면 반영됩니다 (자동 갱신 아님).
- **KIS 토큰 발급 제한**: 한국투자증권 API는 토큰 발급이 1분에 1회로 제한되어 있습니다.
  이 앱은 발급받은 토큰을 서버 메모리/파일에 캐싱해서 재사용하므로, 여러 명이 동시에 검색해도
  대부분 문제없이 동작합니다. 다만 Render가 서버를 재시작하면(예: 절전 후 깨어날 때) 캐시가
  초기화되어 다음 검색 때 토큰을 새로 발급받습니다 — 정상 동작입니다.
- **보안**: KIS_APPKEY/APPSECRET은 Render의 환경변수에만 저장되고, 코드나 GitHub에는
  절대 포함되지 않습니다. 이 값들을 다른 사람과 공유하거나 대화창 등에 붙여넣지 마세요.

---

## 문제가 생기면

- 리포트 화면에 "서버에 KIS_APPKEY/KIS_APPSECRET이 설정되지 않았습니다" → 3번 단계의
  환경변수 등록이 안 된 것입니다. Render 서비스 페이지 → Environment 탭에서 확인하세요.
- "토큰 발급이 막혔습니다 (HTTP 403)" → 방금 전에 이미 토큰을 발급받은 직후입니다.
  60초 정도 기다렸다가 다시 검색해보세요.
- 배포 자체가 실패(빌드 에러) → Render 서비스 페이지의 **Logs** 탭에서 에러 메시지를 확인하세요.
  대부분 `requirements.txt` 관련 문제이니, 이 폴더의 원본 파일이 그대로 올라갔는지 확인하세요.
- "매수 타이밍 신호" 섹션만 안 보임(나머지는 정상) → 일봉 데이터 조회가 여러 번의 API 호출로
  이뤄지다 보니 그중 일부가 실패하면 이 섹션만 조용히 생략되도록 만들어뒀습니다. 리포트 자체는
  정상 생성되니 다시 검색해보시거나, 무료 플랜 특성상 잠깐의 지연 후 재시도해보세요.
